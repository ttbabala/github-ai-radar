# GitHub AI Trend Radar 使用手册

这份手册说明如何在 macOS 终端运行 GitHub AI Trend Radar、查看报告，以及理解它保存的历史记录。

## 1. 它能做什么

每次运行时，程序会从 GitHub 搜索 AI 相关仓库，补充仓库元数据、README 和最近 Release 信息，给项目添加技术领域与技术层级标签，然后保存快照并生成 Markdown 报告。

持续运行后，程序会比较同一仓库在不同时间的 Star 数变化，计算真实的 7 天 / 30 天增长和增长加速度。首次运行没有过去的快照，所以这些增长值会显示“数据不可得”；这不是错误，也不会用猜测值填补。

## 2. 打开终端并进入项目目录

```bash
cd /path/to/github-ai-radar
```

本机使用 `python3` 命令运行，不要用 `python`：

```bash
python3 -m radar
```

## 3. 配置 GitHub Token（推荐）

Token 能提高 GitHub API 的请求额度。本工具只读取公开仓库，不需要写入权限。请在 GitHub 创建 Fine-grained personal access token，并仅授予公开仓库读取所需权限。创建入口：<https://github.com/settings/personal-access-tokens>

在终端中安全输入 Token（输入内容不会显示）：

```zsh
read -s "GITHUB_TOKEN?粘贴 GitHub Token，然后按回车："
export GITHUB_TOKEN
```

然后运行：

```bash
python3 -m radar
```

Token 只在当前终端会话有效。关闭终端后，需要在新的终端窗口重新输入。不要把 Token 粘贴到聊天、源代码、配置文件或 Git 提交中。如果 Token 曾经发到聊天或提交进仓库，请先在 GitHub 撤销它，再创建新的 Token。

没有 Token 时程序仍会尝试运行，但会受到 GitHub 未认证请求额度限制；如果采集不完整，请配置 Token 后再试。

## 4. 日常使用

### 更新数据并生成报告

建议每天或每隔几天运行一次：

```bash
cd /path/to/github-ai-radar
python3 -m radar
```

每次运行会更新当前日期的快照、向历史记录追加本次观察，并生成日报、周报和月报。要计算 7 天增长，至少需要相隔 7 天的有效观察；30 天增长需要至少 30 天。

### 只重新生成报告

这不会访问 GitHub，也不会新增历史数据：

```bash
python3 -m radar --report
```

### 关注一个技术方向

```bash
python3 -m radar --domain agent
python3 -m radar --domain small-model
python3 -m radar --domain mcp
python3 -m radar --domain rag
```

此命令仍会采集并保存完整候选数据；`--domain` 用来筛选生成的报告。匹配依据是项目名称、描述、Topics 和 README 关键词，因此标签是自动分类结果，建议打开项目页核对。

### 选择观察周期

```bash
python3 -m radar --days 7
python3 -m radar --days 30
```

`--days` 用于选择主要观察周期。报告仍会同时展示 7 天和 30 天表格。

也可显式调用：

每次采集都会生成日报、周报和月报；用 `--days 7` 或 `--days 30` 选择报告中重点排序的观察周期。

## 5. 查看输出

运行后终端会打印报告文件路径。报告保存在：

- 日报：`reports/daily/YYYY-MM-DD.md`
- 周报：`reports/weekly/YYYY-Wxx.md`
- 月报：`reports/monthly/YYYY-MM.md`

原始数据保存在：

- 每日快照：`data/snapshots/YYYY-MM-DD.json`
- 逐次历史观察：`data/history/repositories.jsonl`

可以在 VS Code 或其他编辑器中打开最新的 `.md` 报告。也可以在终端列出日报：

```bash
ls reports/daily
```

### 打开动态数据驾驶舱

在一个终端窗口启动本地页面服务：

```bash
cd /path/to/github-ai-radar
python3 -m radar.dashboard
```

然后在浏览器打开 <http://127.0.0.1:8765>。保持启动服务的终端窗口打开；按 `Ctrl-C` 停止服务。驾驶舱每分钟重新读取本地快照与历史文件，不会自行访问 GitHub。要获取新数据，另开终端运行 `python3 -m radar`，页面会自动刷新。

驾驶舱包含项目总量与星标数、可计算的 7/30 天增长、增长加速度、单项目星标历史曲线、中文技术领域分布、项目阶段和历史数据完整度。项目列表提供中文简介；点击“查看项目解读”可以阅读项目用途、所解决的问题、实现方式、研究价值、技术方向和技术层级。未确认属于 AI 的搜索结果会标出“候选误入”，避免把它们当作 AI 项目趋势。原始英文简介折叠保留，方便对照核实。

## 6. 如何读报告

- **Stars**：最近一次从 GitHub 读取的当前 Star 总数。
- **7d Growth / 30d Growth**：当前 Star 数减去目标时间点之前最近一次历史快照的 Star 数。没有合适基线时显示“数据不可得”。
- **Acceleration**：当前 7 天增长减去前一个 7 天区间的增长。没有两段完整历史时不可计算。
- **Trend Score**：配置权重计算的筛选分数。部分输入是基于仓库元数据的启发式代理指标，不是对代码质量或商业价值的客观测量。
- **Lifecycle**：Viral、Emerging、Infrastructure、Strategic、Cooling 是规则辅助标签，应结合增长数据与项目内容判断。
- **Domain / Layer**：根据项目元数据和 README 关键词自动归类，可能有误判。

## 7. 文件用途

| 路径 | 用途 |
|---|---|
| `config/radar.yaml` | 搜索词、技术领域/层级词表、评分权重和生命周期阈值 |
| `data/snapshots/` | 每日仓库数据快照 |
| `data/history/repositories.jsonl` | 每次采集追加一行，供后续计算增长 |
| `reports/` | 面向阅读的 Markdown 报告 |
| `skills/github-ai-radar/` | Agent 工作规则、分类和报告规范 |
| `tests/` | 不依赖 GitHub API 的自动测试 |

## 8. 发布公开趋势报告

仓库包含 `.github/workflows/publish-report.yml`：每天自动采集公开仓库数据、生成可直接阅读的 HTML 报告和历史归档，并部署到 GitHub Pages；也可以在 Actions 页面手动运行 **Publish public trend report**。首次启用时，在仓库 **Settings → Pages** 将构建来源设为 **GitHub Actions**。公开入口为 <https://ttbabala.github.io/github-ai-radar/>，归档为 <https://ttbabala.github.io/github-ai-radar/reports/>。

站点由最近一次成功运行生成，只发布由 GitHub 公开数据产生的报告。工作流使用 GitHub Actions 提供的短期 `GITHUB_TOKEN`，不需要另存个人 Token。采集数据和发布文件都由工作流生成，不会提交回仓库。

不要手动把估算的 Star 数写进快照或历史记录，否则之后的增长计算会失真。备份时可以复制 `data/` 目录。

## 9. 常见问题

### `zsh: command not found: python`

macOS 上使用 `python3`：

```bash
python3 -m radar
```

### 报告里的增长都是“数据不可得”

首次运行没有历史基线。继续定期运行；至少经过 7 天才能计算 7 天增长，至少经过 30 天才能计算 30 天增长。运行 `--report` 只会重做报告，不会增加观测记录。

### 提示 GitHub API 限流或采集失败

确认 Token 已在当前终端设置，再运行 `python3 -m radar`。检查网络连接；如果刚创建的组织 Token 需要管理员批准，等待批准后再使用。不要把 Token 值贴到错误报告中。

### 报告项目似乎和 AI 无关

候选搜索与关键词分类是自动化启发式，可能产生噪声。查看报告中的 GitHub 项目链接和 README；必要时调整 `config/radar.yaml` 中的搜索词或分类关键词。

## 10. 目前的使用边界

命令行程序接受 `--domain` 等参数；它本身不会解析任意自然语言句子。技术分类是关键词匹配，候选集合不是 GitHub 上全部 AI 项目的完整清单。第一次运行产生的是基线快照，趋势结论要等后续运行积累真实数据后才逐步可用。
